## 3. The three real bugs found and fixed this session (all in `src/faults.py` and `src/pipeline.py`)

These were found by actually *inspecting generated data* for statistical sanity (checking whether fault trials showed the expected uncertainty deviation from baseline) rather than just checking the pipeline ran without crashing — worth repeating this kind of check on any future generation run.

### 3.1 `inject_ceiling()` dispatched by literal node-ID string, not role
**File**: `src/faults.py`, function `inject_ceiling()` (~line 296) and `_inject_ceiling_downstream()` (~line 398).
**Bug**: `if target_node == "retriever": ... else: _inject_ceiling_downstream(...)` — a literal string comparison. Only works for the plain `chain` topology's canonical node IDs (`"retriever"`, `"reasoner"`, `"writer"`). Every other topology uses custom IDs (`retriever_a`, `reasoner_1`, `n0_r`, etc.), for which this check silently fails and falls through to `_inject_ceiling_downstream`, which **also** checked by literal string (only recognized `"reasoner"`/`"writer"` exactly) and returned `None` (a skip) for anything else.
**Effect confirmed in the first full generation run**: only 20/118 attempted ceiling trials (~17%) succeeded — nearly all skips were `ceiling_injection_failed_<custom_node_name>`, not genuine "answer survived stripping" skips.
**Fix**: added a `role: Optional[str] = None` parameter to `inject_ceiling()` and `_inject_ceiling_downstream()`; dispatch/lookup now uses `role` (when provided) instead of the node-ID string. All three call sites (`run_study1.py`, `run_study2.py`, `run_study_vllm.py`) updated to pass `role=topo.nodes[tn].role`.
**Verified fix**: mock dry-run of the full 20-topology pool went from 20→103 ceiling trials (5x), skip count from 98→~15-19 (all now genuine).

### 3.2 Downstream ceiling's hardened instruction was computed but never applied
**File**: `src/pipeline.py`, function `build_prompt()` (~line 125).
**Bug**: `_inject_ceiling_downstream()` computes a "hardened" instruction (e.g. "at most 2 reasoning steps") meant to force genuine information loss for Reasoner/Writer-targeted ceiling faults, and stores it in `fault_config["_hardened_instruction"]`. **`build_prompt()` never read this key** — it always used `node.instruction` (the topology's normal instruction) regardless of fault_config. Net effect: **every ceiling fault targeting Reasoner or Writer ran with zero actual degradation** — the model saw the completely normal prompt, despite the trial being labeled `"ceiling"`.
**How this was caught**: after the first full run, checked whether fault trials showed the expected uncertainty increase vs. clean baseline. Noise and contamination did; ceiling did not (in 18/20 cases it stayed flat or went *down*, since forced-brevity-shaped output happened to be less varied than free-form output when the instruction WAS occasionally close to hardened by coincidence — but mostly because no fault was applied at all).
**Fix**: `build_prompt()` now checks `fault_config.get("type")=="ceiling" and fault_config.get("target_node")==node_id and fault_config.get("_hardened_instruction")`, and substitutes it for `node.instruction` when true. Verified via direct unit test: hardened instruction is used only for the correctly-targeted node, normal instruction elsewhere, no leakage across nodes.
**This fix applies automatically to `run_study1.py`/`run_study2.py` too**, since they all route through the same shared `build_prompt()`.

### 3.3 Contamination substitute bank had no self-exclusion safeguard
**File**: `src/faults.py`, function `inject_contamination_downstream()` (~line 234).
**Bug**: the substitute bank (pool of "wrong" answers to swap in) is built once per topology from **all** questions assigned to that topology — including the very question currently being contaminated. Nothing excluded a question's own clean output from being drawn as its own "corruption." With only 2-4 questions per topology (see Section 3.5's coverage-strategy design), this was a real, un-guarded risk — not confirmed as having actually produced bad data in the first run (real model output is diverse enough that exact self-match by chance is unlikely), but a genuine code-level gap.
**Fix**: `substitute_bank = [s for s in substitute_bank if s != clean_parent_output]` added before selection; returns `None` (skip) if that empties the bank.
**Also cleaned up**: `inject_contamination_retriever()` had a hardcoded dead `"target_node": "retriever"` field in its own return dict (harmless in practice since every caller discards it and rebuilds fresh with the real node ID, but misleading) — added a `target_node` parameter, now honored correctly.

### 3.4 (Infrastructure, not a data bug) Real-time log streaming
Covered in Section 2 — the first full-run kernel used a buffering `subprocess.run()` pattern that made it look potentially stuck for ~2+ hours before being diagnosed. Fixed in the current kernel entry script (`kaggle_fullrun_entry.py` in the scratchpad — **will need to be recreated in a new session**, see Section 6).

### 3.5 Known limitation, NOT fixed (pre-existing, low severity)
Contamination on a multi-parent node (e.g. `reasoner` in `dual_retriever_fanin`, fed by `retriever_a` + `retriever_b`) only corrupts the **first** parent (`parents_of(topo, tn)[0]`) — the other parent(s) stay clean. This matches the original `run_study1.py`/`run_study2.py` design (not introduced this session), doesn't produce wrong labels (the trial genuinely is contamination-affected, just partially), and was left as-is given time constraints. Worth revisiting if multi-parent contamination trials need to be "fully" corrupted for a stronger signal.

## 4. Real measured timing data (first full run, before the fixes — still useful for ETA estimation)

A full 20-topology run took **~4h20min** end-to-end (21:52 → 02:12). Key finding: **per-topology time correlates with how many Reasoner-role nodes run per batched round**, not simple node count or chain depth:

| Reasoner nodes in topology | Typical duration |
|---|---|
| 1 | ~7-9 min |
| 2 | ~9-11 min |
| 3 (sequential, e.g. deep chain) | ~12 min |
| 3 (parallel, same round) | ~22 min (worst case) |
| 4 (parallel) | ~21 min |

Reasoner generation uses a larger token budget (`MAX_TOKENS_REASONER=600` vs. 350 for others) and longer chain-of-thought — multiple Reasoners in the *same* batched round multiply this cost per round, more than depth alone does. Model load (~8-10 min) is a one-time cost at the start, not per-topology.

**Given the bug fixes increased total records from 410→~490 (more ceiling trials now actually succeed and generate)**, expect this run to take **somewhat longer than 4h20min** — budget ~4.5-5.5h.

## 7. Reusable kernel entry script (recreate this file if launching another Kaggle run)

Save as `kaggle_fullrun_entry.py` in a fresh kernel directory, alongside a `kernel-metadata.json` (template also below):

```python
import os
import subprocess
import sys
import time

CODE_ROOT = "/kaggle/input/datasets/aryanmahajan7/btp-pipeline-code"

def log(msg):
    print(f"[{time.strftime('%H:%M:%S')}] {msg}", flush=True)

log(f"=== Debug: contents of {CODE_ROOT} ===")
if os.path.isdir(CODE_ROOT):
    for sub in ("src", "scripts", "data", "dataset"):
        subpath = os.path.join(CODE_ROOT, sub)
        if os.path.isdir(subpath):
            log(f"  {sub}/: {os.listdir(subpath)}")
else:
    log(f"CODE_ROOT does not exist: {CODE_ROOT}")
    for root, dirs, files in os.walk("/kaggle/input"):
        log(f"  dir: {root} -> {dirs} {files[:5]}")
    sys.exit(1)

log("=== Installing vllm ===")
result = subprocess.run([sys.executable, "-m", "pip", "install", "-q", "vllm"],
                        capture_output=True, text=True)
log(result.stdout[-800:])
if result.returncode != 0:
    log("PIP INSTALL FAILED"); log(result.stderr[-3000:]); sys.exit(1)
log("vllm installed.")

os.environ["BTP_BACKEND"] = "vllm"
os.makedirs("/kaggle/working/logs", exist_ok=True)

log("=== Running FULL dataset generation (streaming) ===")
cmd = [
    sys.executable, "-u",
    os.path.join(CODE_ROOT, "scripts", "run_study_vllm.py"),
    "--topology-pool", os.path.join(CODE_ROOT, "dataset", "topology_pool.json"),
    "--examples-json", os.path.join(CODE_ROOT, "data", "study30_examples.json"),
    "--k", "5", "--batch-size", "15",
    "--examples-per-topology-full-grid", "2",
    "--examples-per-topology-partial", "4",
    "--log-path", "/kaggle/working/logs/dataset_trials.jsonl",
    "--skip-log-path", "/kaggle/working/logs/dataset_skipped.jsonl",
]
log("CMD: " + " ".join(cmd))

proc = subprocess.Popen(cmd, cwd=CODE_ROOT, stdout=subprocess.PIPE,
                        stderr=subprocess.STDOUT, text=True, bufsize=1,
                        env={**os.environ})
for line in proc.stdout:
    print(f"[{time.strftime('%H:%M:%S')}] {line.rstrip()}", flush=True)
proc.wait()

log(f"=== Exit code: {proc.returncode} ===")
if os.path.exists("/kaggle/working/logs/dataset_trials.jsonl"):
    with open("/kaggle/working/logs/dataset_trials.jsonl", encoding="utf-8") as f:
        n = sum(1 for _ in f)
    log(f"=== {n} trial records written ===")
sys.exit(proc.returncode)
```
